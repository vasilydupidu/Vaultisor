# Vaultisor 5.2.0 — аппаратный smoke-test

Проверка на реальном железе того, что fault-injection тесты покрывают только
программными подменами: Windows Hello (платформенный WebAuthn), Рутокен MFA
(FIDO2, hmac-secret), TPM 2.0 (Device Secret), DPAPI.

**Все девять сценариев обязательны.** Тег `v5.2.0` ставится только после
того, как каждый пройден.

**Сборка:** `release\Vaultisor-5.2.0.exe`; перед запуском сверьте SHA-256
(`Get-FileHash`) с указанным в отчёте о сборке. Exe скопируйте в **пустую**
папку: хранилища предыдущих версий сборкой 5.2.0 не открываются.

**«Перезагрузка»** — полный перезапуск Windows, а не только приложения:
TPM-ключ, ключи Hello, DPAPI и внешний checkpoint в
`%LOCALAPPDATA%\Vaultisor\SecurityCheckpoints` должны пережить именно его.

**Журнал.** Релизная сборка журнал не пишет. Для smoke-test запускайте её
с диагностикой — журнал появится в `vault\logs\Vaultisor-diag*.log`:

```powershell
$env:VAULTISOR_DIAG = "1"; .\Vaultisor-5.2.0.exe
```

**При любом ❌:** не продолжайте этот сценарий, сохраните журнал, запишите номер
шага и что именно увидели (текст ошибки, что появилось на экране).

**После проверки** удалите тестовое хранилище и файлы частей B и C: обе части
вместе дают полный доступ к хранилищу.

## 7. Привязка FIDO2 к устройству

| # | Шаг | Ожидание | Итог |
|---|-----|----------|------|
| 7.1 | Привязать Рутокен (как 2.1), проверить вход FIDO2 | Вход | |
| 7.2 | Закрыть приложение, скопировать папку с exe и `vault` на **другой ПК** с Windows | — | |
| 7.3 | На другом ПК: запустить, войти FIDO2 тем же Рутокеном (верный ПИН токена) | **Отказ** — нет Device Secret из TPM и DPAPI исходного ПК | |
| 7.4 | На другом ПК: войти PIN | **Отказ** — хранилище открывается только восстановлением по долям | |

Если второго ПК нет: повторить 7.2–7.4 в **другой учётной записи Windows** на
этой машине. Это подтверждает только привязку к пользователю (DPAPI); привязку
к машине (TPM) всё равно нужно проверить на втором ПК — до этого пункт 7
остаётся частичным.
